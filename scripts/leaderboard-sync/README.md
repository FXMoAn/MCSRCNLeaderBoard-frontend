## import_20260910.sql 做了什么

新增 56 条成绩、新建 31 个玩家档案、回填 `users.bili_id`、给 `runs` 加 `bvid` 列、
改 6 个昵称并清掉 1 个首尾空格。不删除任何 runs。

`runs` 的 `date` / `videolink` / `igt` 都是 NOT NULL，脚本按站点既有约定处理：
空日期写 `''`，无视频的写 `No Video - <文档名次>`，成绩本身非法的（如文档里的
`38:~`）不入库，列在报告 2b。

## 怎么执行

1. Supabase Dashboard -> SQL Editor，整段粘贴运行。结尾默认是 `ROLLBACK;`，
   所以第一遍是**真正的 dry-run**：会返回校验数字，但生产数据零变化
   （已在本地 Postgres 上验证 users/runs 内容逐字节不变、也不留临时表）。
2. 核对数字（三个"异常"项应为 0），把 `ROLLBACK;` 改成 `COMMIT;` 再运行一次落库。
3. 需要回退时按文件末尾注释里的备份表操作。

可重复执行：同一 BV、或同玩家同成绩已存在则跳过（已验证重跑时新增为 0）。

## 重新生成

    python3 generate.py

读同目录的 `doc_*.tsv` + `bili_bvid_owner.json`，并用仓库 `.env.local` 里的 anon key
拉当前 `runs`/`users` 做对比，产出 `import_<TAG>.sql` 与 `import_report.txt`。
换一批数据时把 `generate.py` 里的 `TAG` 改成当天日期，备份表名会随之变化。

## 数据来源与边界

- 身份用 B站 `mid`（UP主永久数字 ID），不用昵称：文档名和站点名都会过期。
  解析缓存在 `bili_bvid_owner.json`，362 个 BV 中 291 个成功，71 个失败
  （62002 稿件不可见 60、62012 权限受限 11）；失败的不回填 `bili_id`，也不改昵称。
- `doc_*.tsv` 是 2026-09-10 从文档机器化导出的快照，两个 tab 已统一成同一列序：
  名次 / B站id / 用时 / 毫秒 / 视频BV或链接 / seed / 日期 / 备注。
  注意文档里两个 tab 的原生列结构不同：`1.16+RSG` 是 `5=毫秒 7=seed 8=日期 10=备注`，
  `1.13-1.15 RSG` 是 `5=路线/打法 7=日期 9=备注`（没有毫秒列，毫秒写在备注里如
  `890ms`，导出时已提取到毫秒列；路线/打法未保留）。
- 刻意**没有**自动处理、全部列在 `import_report.txt` 里待人工的：
  档案合并 2 组、跳过的新增 13 条、仅 B站单方面改名的 49 条。
